# Codex + CapCut для ПК: навыки для монтажа видео

Набор инструкций и инструментов для создания и доработки видео в Codex с локальным проектом CapCut на Windows. Codex готовит материалы и, при поддерживаемой версии проекта, записывает таймлайн, пока приложение закрыто.

Для облачного монтажа есть [отдельный комплект CapCut Web](https://github.com/umbrel-la/codex-capcut-web-skills).

## Что умеет

- Выбрать законченную историю из длинного исходника и подготовить вертикальный рилс.
- Удалить заказанные паузы и дубли, сохранив смысл речи.
- Добавить к готовому видео motion-графику, фон, надписи или субтитры без обязательной перенарезки.
- Подготовить видеослои, отдельные тексты и звук, локальный MP4 и проект CapCut при поддерживаемой схеме.
- Продолжить работу по `STATE.md`; использовать Higgsfield для нужных материалов в согласованном бюджете.

Для нового вертикального рилса без других указаний ориентир — 30 секунд и 1080×1920. Для оформления готового ролика задача сохраняет его длительность, склейки и звук. Текущий настольный адаптер рассчитан на вертикальный холст 9:16 от 1080×1920; другой формат требует проверки и, возможно, доработки инструмента.

## Что потребуется

1. Windows, установленный настольный CapCut и Codex с доступом к локальным файлам.
2. Node.js и FFmpeg с `ffprobe` в системном `PATH`.
3. Для автоматической локальной транскрибации — отдельно установленный Python, `faster-whisper` и совместимая локальная модель. Скрипт не скачивает модель автоматически.
4. Higgsfield — необязательное отдельное подключение для генерации материалов.

Облачный CapCut MCP для записи локального проекта не обязателен.

## Установка

```bash
git clone https://github.com/umbrel-la/codex-capcut-desktop-skills.git
```

Откройте скачанную папку как проект в Codex и создайте в ней чат. Инструкции — в `AGENTS.md`, навыки — в `.agents/skills`. Если репозиторий открыт как подпапка другого проекта, укажите его путь и попросите прочитать его `AGENTS.md`.

Скопируйте пути к своим исходникам или приложите файлы. Личный проект и видео не входят в репозиторий и не должны попадать в публичный Git.

## Как начать монтаж

1. Опишите задачу, исходник, желаемую длительность и стиль. Можно дать референс или описать оформление словами.
2. Если нужен редактируемый проект, создайте в CapCut **новый пустой проект** с уникальным именем и сообщите его Codex. Анализ и предварительные материалы можно готовить раньше.
3. Сохраните работу и полностью закройте CapCut перед записью файлов проекта. Адаптер проверит схему, создаст резервную копию и остановится при конфликте или неподдерживаемом формате.
4. После записи откройте проект в CapCut и проверьте расположение слоёв, текст, звук и наличие файлов. Экспортируйте в приложении, если нужен именно экспорт CapCut.

Пример нового рилса:

```text
Работаем в CapCut на ПК. Из [путь к видео] сделай рилс
на 30 секунд про [идея]. Референс: [путь или описание].
Новый пустой проект CapCut: [название]. Нужны проект и MP4.
```

Пример оформления готового видео:

```text
Добавь к [путь к видео] motion-графику и более динамичный фон.
Сохрани длительность, порядок сцен, речь и звук. Стиль: [описание].
Подготовь отдельную новую версию и укажи, какие слои редактируются.
```

Если фон уже объединён с изображением в MP4, его замена может потребовать исходников, масок или пересборки. Сложная графика может быть подготовлена отдельным видеослоем с сохранённым исходным кодом, а не набором отдельных фигур CapCut.

## Состав и хранение

| Навык | Назначение |
|---|---|
| `reel-director` | Выбор сценария и полный процесс создания рилса |
| `capcut-rough-cut` | Отбор фрагментов и чистка речи |
| `capcut-finish` | Motion, фон, субтитры, звук и точечные правки |

Подробный необязательный [шаблон задания](ПРОМПТ_ДЛЯ_НОВОГО_ЧАТА.txt) предназначен для нового рилса. Правила выбора этапа находятся в [task-routing.md](.agents/skills/reel-director/references/task-routing.md).

Работы размещаются в `_монтаж/reel_NN` и исключены из Git. `STATE.md` хранит прогресс и пути. Папки `prepared`, графику и звук, на которые ссылается проект, не перемещайте без перепривязки.

`desktop.mjs` поддерживает `doctor`, `projects`, `inspect-project`, `validate`, `prepare`, `render`, `stage`, `apply`, `check` и `restore`; схема плана и ограничения описаны в [desktop-plan.md](.agents/skills/reel-director/references/desktop-plan.md), порядок записи — в [desktop-project.md](.agents/skills/reel-director/references/desktop-project.md).

## Совместимость и проверки

Адаптер проверяет незашифрованную схему `360000` с версиями `185.0.0`, `189.0.0` или `191.0.0`. Это проверка структуры, а не гарантия совместимости каждой версии CapCut. Сначала проверьте короткий ролик в новом пустом проекте. Сохранение файлов, открытие проекта в приложении и экспорт — отдельные результаты. Ручные изменения существующего проекта не перезаписываются автоматически.

Локальные проверки используют синтетические медиа и проект, без платных API и изменений настоящего проекта:

```bash
node tests/check-kit.mjs
```

Шрифт Onest включён с [лицензией SIL OFL](assets/fonts/OFL.txt). Шаблоны в `assets/capcut` предназначены для совместимости адаптера; проект основан на адаптации рабочего процесса монтажа для Codex и CapCut. Права на другие сторонние материалы и медиа проверяются отдельно.
